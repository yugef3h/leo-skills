# 核心结论先分清：自动维护 `CLAUDE.md`、生成 `specs.md`、写进度文档、自动 git commit 是**Claude Code 内置多工具组合协同完成**，不是单一工具，拆分每个执行主体：
## 一、负责生成/持续维护 specs、progress.md、CLAUDE.md 的底层工具
1. **file_write（文件写入工具）**
    所有 md 文件落地的底层载体：
    - 初次拆解需求生成 `specs.md`；
    - 每轮迭代更新 `progress.md` 工作进度；
    - 新建、增量更新、补全、修正项目根目录 `CLAUDE.md`；
    读取旧内容靠配套工具 `file_read`，实现增量追加，不会覆盖全部内容，做到长期自动维护文档。

2. **spec-generator 内置任务技能（核心逻辑层）**
    这是「自动产出规格文档」的调度模块，由 Claude Code 原生内置：
    - 解析对话需求、接口、数据库、业务规则、技术约束；
    - 结构化整理输出到 `specs.md`；
    - 同步同步关键项目配置、项目规范、上下文沉淀到 `CLAUDE.md`；
    只要开启自动归档配置，每次需求变更、架构调整都会主动更新两份文档。

3. **project-context-manager 项目上下文管理器（CLAUDE.md 专属维护逻辑）**
    专门负责持续维护 `CLAUDE.md` 的技能：
    - 自动记录项目技术栈、目录结构、开发规范、历史修改记录、环境配置、远程会话配置（remote control）；
    - 新增模块、修改架构、切换功能时自动补全、修正文档内容；
    - 给后续会话提供全局项目上下文，也是你远程手机端能看懂项目全貌的关键。

## 二、自动 git add / git commit 是哪个工具实现？
**bash / shell 终端执行工具**
1. 文档更新完成后，内置自动化工作流会调用 shell 工具执行 git 命令：
    ```bash
    git add ./specs.md ./progress.md ./CLAUDE.md
    git commit -m "Auto update spec & project context & progress log"
    ```
2. 触发条件：配置开启 `auto_git_commit_docs`，每次自动写入 md 文件后，自动提交变更到本地仓库；
3. 优势：10w+ 行大型项目下，所有需求、进度、项目规范变更全部留痕，不用手动保存文档、手动提交代码文档。

## 三、整套联动流程（对应你大型全栈项目场景）
1. 你下发开发指令 → spec-generator 梳理业务/技术规范；
2. 调用 file_read 读取原有 `specs.md` / `CLAUDE.md`；
3. file_write 增量更新三份文档；
4. project-context-manager 校验、补全 `CLAUDE.md` 项目全局信息；
5. shell 工具自动执行 git 提交留存变更；
6. 开启 remote control 后，手机 App 实时同步对话 + 本地全部 md 文件，远程查看完整项目档案。

## 四、补充区分第三方工具（小龙虾）和官方这套能力
小龙虾仅做**对话远程投屏**，没有文件读写、自动归档、git 提交能力；
而 Claude Code 原生这套是「远程查看 + 自动文档沉淀 + 版本自动留档」一体化，适配你十万行级复杂全栈项目，长期迭代不会丢失需求与过程记录。

## 五、开关控制（不想自动提交/自动写文档可关闭）
会话内输入 `/config`，调整这几个配置项：
- `auto_generate_specs`：自动生成更新 specs.md
- `auto_update_claude_md`：自动维护 CLAUDE.md
- `auto_log_progress`：持续更新进度文档
- `auto_commit_doc_changes`：文档变更后自动 git 提交



### 一、配置开关生效范围分两种，不是全局一刀切
1. **会话级临时开关**
直接在当前窗口输入 `/config` 修改的参数，**仅对本次打开的项目会话生效**，换文件夹、新开终端会话就会重置为默认值。

2. **全局永久开关（所有项目统一生效）**
```bash
claude config edit
```
修改全局配置文件里的 `auto_generate_specs` / `auto_update_claude_md` / `auto_commit_doc_changes` 等项，保存后**本机所有项目、所有新会话都会自动启用这套归档+自动提交逻辑**。
如果部分项目不想自动提交/自动写文档，可以进入项目目录后用 `/config` 单独覆盖全局配置，局部关闭。

### 二、这套自动化对十万行级混合开源借鉴项目的价值
1. **specs.md 解决多开源整合混乱问题**
你项目融合多个开源仓库，不同库的接口规范、数据结构、业务逻辑互相冲突；AI 会全程梳理、统一整理到 specs：
- 各开源组件原始能力边界
- 你二次改造后的修改点、兼容适配规则
- 业务新增需求、接口入参出参、数据库约束
后续迭代、重构时不用反复翻开源源码和聊天记录，直接看规格文档。

2. **CLAUDE.md 持续维护项目全局上下文**
它是项目专属记忆库，完全由内置 `project-context-manager` 工具驱动自动更新：
- 技术栈、目录结构、打包/部署脚本说明
- 依赖版本、开源第三方模块改造记录
- Remote Control 远程配置、本地开发环境要求
每次新增模块、重构架构、切换功能都会自动修正，新开会话不用重新介绍项目背景。

3. **progress.md 完整留存全流程开发过程**
每一轮调试、改bug、需求调整、远程手机下发的修改指令全部增量写入，复盘迭代、排查历史问题一目了然。

4. **自动 git commit 实现变更永久留痕**
依托 shell 工具自动执行提交，所有 md 文件改动都会生成独立提交记录：
- 区分代码改动和文档规范改动
- 提交信息标准化，方便回溯哪次需求调整修改了 specs / CLAUDE.md
多人协作、长期迭代时，文档变更有版本追溯，不会出现文档和代码不同步、历史方案丢失的情况。

### 三、搭配 Remote Control 的完整闭环
本地自动生成、更新、提交三份文档 + 远程手机实时同步对话与文件：
外出随时查看项目规格、开发进度，远程下发修改指令后，AI 同步更新文档并自动提交，十万行大型项目不用频繁回到电脑整理文档、手动归档，大幅减少重复梳理需求、记录开发过程的工作量。

### 四、小补充（按需灵活管控）
- 不想频繁自动提交：关闭全局 `auto_commit_doc_changes`，需要归档时手动执行一次提交即可；
- 小型demo不需要 specs：单独在项目 `/config` 关闭 `auto_generate_specs`；
- 完全不需要自动维护 CLAUDE.md：关闭 `auto_update_claude_md`，仅保留进度日志。
