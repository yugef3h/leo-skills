# AI工程化落地完整规范体系（Spec\+Harness\+AGENT\+TDD开发模式）

## 一、核心核心体系：Spec 规范定义 \+ Harness 自动化校验

### 1\. Spec（规范层：前置定义，统一标准）

核心定位：AI开发的**需求文档\+技术方案规范**，所有AI代码生成、功能开发必须严格遵循Spec，从源头避免需求跑偏、架构失控。

核心作用：统一开发标准、约束功能边界、定义技术细节、规范输出格式，是后续所有任务拆解、代码开发、验收测试的唯一依据。

Spec 核心包含内容：

- 统一规范：明确业务/语言/功能的统一设计标准、开发准则

- 边界约束：清晰定义功能范围、禁止范围、上下游依赖边界

- 技术细节：核心逻辑、实现思路、技术选型、兼容规则

- 文档配套：标准化输出格式、注释规范、落地配套文档要求

关键执行规则：

- Spec 定稿前必须**多轮头脑风暴、细节对齐**，涉及资金、付费类核心功能，必须逐项确认所有细节，无异议后再进入下一环节

- Spec 编写阶段**不生成任何Task**，避免冗余Token消耗、流程混乱

- **绝对强制顺序约束**：Spec 必须人工Review对齐业务目标，Spec错位=代码全面跑偏，**严禁跳过Spec、严禁直接根据口头需求生成代码**，必须严格遵循**先文档、后代码**的绝对开发顺序，这是AI工程化不返工的核心前提

### 2\. Harness（校验层：自动化验收，量化质量）

核心定位：AI代码/功能的**自动化质量校验、结果验收体系**，替代人工主观判断，实现开发结果可量化、可断言、可落地。

核心作用：校验AI生成结果是否符合客户预期、是否符合Spec规范，自动化检测代码质量，规避隐性BUG、架构问题、逻辑偏差。

Harness 四大核心执行模块：

- 场景数据准备：提前覆盖全量业务场景、边界场景、异常场景的输入数据集

- 执行环境定义：明确校验执行方式（SQL执行/API调用/本地运行等）

- 逻辑断言校验：对标单测断言机制，判断功能逻辑、业务结果是否完全符合Spec定义

- 量化打分评估：输出可量化的质量指标，完成标准化验收

## 二、标准开发流程：Spec → Plan → Task → Code

优化后完整闭环流程，层层递进，彻底提升AI开发稳定性、可维护性、可复盘性，杜绝无序开发。

完整流程链路：**需求\&技术评审 → 输出Spec文档 → 制定执行Plan → 拆解精细Task → AI生成代码 → Harness自动化验收 → 迭代修正/提交**

### 各环节强制执行规则

1. **项目初始化规则**

    - 新项目：优先自动生成 AGENTS\.md 全局规则文件，再启动需求梳理

    - 老项目：先基于现有代码整理完整Docs文档，排查现有架构、逻辑、规范问题，完成所有细节讨论对齐后，再编写新代码

2. **开发前置规则**：严禁打开项目直接写代码，必须先讨论、对齐需求，由AI输出完整Spec至docs目录，人工Review所有细节，无偏差后再推进

3. **任务拆解规则**：Spec定稿后，拆解为精细化Task，**禁止巨型Task**（不利于Review、迭代、问题定位）；每个Task必须包含：状态、依赖关系、Checklist、对应关联Spec文档，所有问题在代码生成前修正完毕

4. **代码生成规则**：AI生成代码阶段，禁止输出多余自然语言，指定单一Task定向实现，保证代码聚焦、无冗余

5. **绝对流程兜底规则**：出现问题循环回溯「需求讨论→Spec修正→Task调整→代码重写」全流程；**严禁先写代码、后反向补文档**，该操作会直接导致架构混乱、规范失效、无法维护；若紧急场景需要先行开发验证效果，必须将所有增量改动完整回写Docs、重构梳理全套规范，对齐Spec后再提交，杜绝流程倒置

6. **规范沉淀规则**：持续提炼优质开发规范、避坑经验、落地标准，自动更新至 AGENTS\.md，形成项目专属可复用规则体系

7. **模型选型规则**：优先使用 Codex 等海外轻量化模型，减少Token消耗、提升生成效率，兼顾质量与速度

8. **提交规范**：采用「一个Task一次提交」模式，避免批量修改导致正确代码被覆盖改错，保证迭代可控、可回滚

## 三、AGENTS\.md 规则体系核心准则

1. **核心强制规则**：固化 **Spec → Plan → Task → Code** 开发链路，强制AI严格按该流程执行，从规则层面杜绝跳步开发

2. **AGENTS\.md 容量风险约束**：**AGENTS\.md 文件体量越大，实际约束效力越弱**，过度堆砌规则会导致AI识别跑偏、规则失效，等同于无规则；严格执行**轻量化、精简化、按需加载**原则，只保留核心强制规则，保证规则精准、有效、可执行

3. **动态迭代原则**：不手动编写、修改 Spec 和 AGENTS\.md，全程由AI基于落地实践自然语言迭代、自动更新

## 四、AI工程化 TDD 落地核心难点与解决方案

TDD落地核心难点：不在于Spec编写，而在于**如何自动化防偏、纠偏**，杜绝AI开发常见的**功能正常、架构崩盘、完全不可维护**的核心风险，从流程和规则层面强制约束代码与架构一致性。

### 核心落地方案

1. **Spec与代码一致性校验**：由AI自动化完成双向Review，保证代码逻辑、架构、细节完全对齐Spec规范，杜绝偏差

2. **自动化重构机制**：项目迭代中的重构工作由AI全权执行，人类仅提供方向性建议，无需逐行Review代码；仅需通读主业务链路，定位架构、逻辑问题，反馈给AI后，由AI举一反三完成全局自查、修正、重构文档更新

3. **核心本质**：软件工程完整流程、规范、闭环完全保留，仅将执行主体从人工替换为AI Agent，保证工程质量不降级

## 五、现存问题与现状说明

**AI自动化测试用例核心风险（重点标记）**：当前完全由AI自主编写、生成的测试用例存在**漏洞多、稳定性差、覆盖不全、逻辑失真**等各类问题，暂不支持全量自动化落地；现阶段必须依托 Harness 自动化校验体系叠加**人工辅助校验、量化兜底审核**，绝对不能完全依赖AI生成的测试用例做验收，该问题需等待AI模型、技术能力持续迭代进化后逐步优化。
