# 中小团队 Vibe Coding 组件复用最佳落地实践（单仓库、无中台、无MCP服务、控制上下文开销）
## 一、核心设计目标（解决两大痛点）
1. 强制AI优先复用内部组件，杜绝重复造轮子；
2. 严格控制上下文Token，不每次加载全量组件文档，避免对话臃肿、推理变慢；
3. 轻量化落地，不新增运维服务，仅依赖代码文件+Cursor/Cline原生能力+ESLint。

## 二、分层架构：三类文件各司其职，隔离Token消耗
### 1. 底层永久约束：`.cursorrules`（不占对话上下文，全局生效）
定位：系统级规则，工具启动一次性加载，**只写行为逻辑，不放任何组件代码示例**，Token极小。
直接复制使用：
```
# 全局强制编码规则
## 组件复用核心流程
1. 收到页面/模块开发需求，先执行工具检索：
   search_code 检索目录 src/components/common、src/components/biz
2. 仅对检索匹配度最高的1~3个组件执行 read_file 读取TS类型与调用示例；禁止一次性读取全部组件文件。
3. 优先复用现有组件，现有组件无法满足需求时，输出组件扩展方案，禁止复制组件源码重写一套。

## 导入与编码规范
1. 组件统一使用 @/components/xxx 导入，禁用多层相对路径；
2. 调用组件必须严格遵守原有Props类型，不得私自新增未定义参数；
3. 禁止原生手写button/input/table/modal/select等基础UI；禁止引入shadcn/mui/element-plus等外部UI库；
4. 列表统一 BizSearchTable，表单统一 BizForm，弹窗统一 ModalWrapper。

## 上下文节约硬性要求
1. 非当前业务场景匹配的组件，绝不主动读取、不加入对话上下文；
2. 同一会话内已读取过的组件，缓存复用，不再重复调用read_file；
3. 禁止自动加载项目内全部组件文档。
```

### 2. 分片式组件资产文档（按需注入，控制单次上下文大小）
把庞大组件清单拆分为轻量化分片，杜绝一次性全量载入对话：
```
src/components/
├── COMMON.md      # 基础通用组件：Button、Input、Tag、Modal（体积最小，高频通用）
├── BIZ_TABLE.md   # 列表分页、筛选、表格组件
├── BIZ_FORM.md    # 搜索表单、弹窗表单、上传组件
└── SPECIAL.md     # 小众特殊业务组件（极少用到，平时不引入）
```
每个分片只写：组件名称、适用场景、最简调用示例，不堆砌冗余源码。
示例 COMMON.md：
```
# 通用基础组件
1. BaseButton
适用：所有按钮操作
<BaseButton type="primary" onClick={handleAdd}>新增</BaseButton>
2. StatusTag
适用：状态文字展示
<StatusTag status={row.status} />
```

### 3. 自动化兜底：自定义ESLint规则（开发+提交双拦截）
解决AI侥幸违规、人工Review遗漏问题，完全不依赖AI上下文：
1. 本地实时校验：检测代码中原生table/button/input、非法第三方UI导入、重复组件实现；
2. Git提交校验：husky钩子触发lint，违规代码阻断提交；
3. 规则白名单：少量特殊场景可注释豁免，避免误报。

## 三、标准开发流程（固定操作，平衡复用 & 上下文开销）
### 步骤1：新建会话，不用重复写约束
`.cursorrules` 全局生效，无需每次Prompt重复写复用规则。

### 步骤2：按需引入对应分片组件文档（只引入当前页面需要的）
列表页只引入表格+通用组件，表单页只引入表单+通用组件，无关文档绝不加载。
标准Prompt模板：
```
@src/components/COMMON.md
@src/components/BIZ_TABLE.md
需求：生成客户管理列表页面，支持分页、状态筛选、批量删除、单行编辑弹窗
执行流程：
1. 检索现有表格组件，复用而非自建；
2. 弹窗使用内部ModalWrapper，操作按钮使用BaseButton；
3. 输出完整TSX代码，组件传参严格遵循原有类型定义；
4. 若现有组件缺少能力，先给出扩展方案，不要重新实现表格。
```

### 步骤3：AI自动工具检索，补充组件源码
AI会根据检索结果，仅读取匹配到的组件tsx源码，少量代码加入本次上下文，会话结束自动销毁，不累积冗余信息。

### 步骤4：本地ESLint自动校验，拦截违规代码
AI生成代码后立刻触发lint，出现手写原生组件、非法导入直接报错，即时修改。

### 步骤5：MR评审简化关注点
Review不再检查是否重复造轮子，只关注业务逻辑、组件传参是否合理。

## 四、上下文优化关键策略（解决你担心的重复读取浪费Token）
1. **同会话缓存机制**
   一次会话中读取过的组件，Cursor会缓存元信息，后续同类型页面不再重复调用read_file读取源码；新开会话才会重新检索。
2. **分片隔离，最小化注入**
   绝不一次性引入 COMMON + TABLE + FORM + SPECIAL 全部文档，只引入当前页面所需1~2个分片，单次上下文组件素材控制在50行以内。
3. **区分“系统规则”和“临时素材”**
   .cursorrules 常驻底层，不占用对话窗口Token；组件分片、组件源码属于本轮临时素材，对话结束自动清空，不会叠加。
4. **禁止长清单写入规则文件**
   规则只写行为约束，不存放大量组件示例，防止全局系统提示词过重拖慢AI响应。

## 五、配套团队协作规范（工业化落地必备）
1. 脚手架标准化
   新项目初始化自带 `.cursorrules`、components分片文档模板、自定义eslint配置，全员统一标准，无需手动搭建。
2. 组件资产更新流程
   新增通用业务组件后，同步更新对应分片MD文档，提交入库；所有成员AI下次开发可自动检索复用。
3. 组件扩展统一流程
   AI发现现有组件无法满足需求，禁止直接复制修改：
   - 方案A：外层封装Wrapper拓展；
   - 方案B：提交需求给前端负责人，统一迭代基础组件库；
4. 新人统一培训
   只培训两点：①开发时按需@对应组件分片；②看懂lint报错，优先复用内部组件。

## 六、整套方案优劣对比（中小团队最优解）
| 方案                | 上下文开销 | 落地成本 | 适用场景               |
|---------------------|------------|----------|------------------------|
| 全量组件清单粘贴Prompt | 极高，臃肿 | 0成本    | 禁用，长期开发卡顿     |
| 仅.cursorrules无分片文档 | 极低 | 低 | 组件复用率差，AI看不见示例 |
| 本方案：规则+分片按需注入+ESLint | 低可控 | 极低（纯文件） | 10~50人单仓库中小团队 |
| MCP组件中台服务 | 极低 | 高，需部署 | 多仓库大型团队，不推荐中小团队 |

## 七、极简落地执行清单（30分钟完成搭建）
1. 项目根目录创建 `.cursorrules`，粘贴上文规则；
2. 在src/components下拆分 COMMON/BIZ_TABLE/BIZ_FORM/SPECIAL 分片文档；
3. 配置自定义ESLint规则，添加husky提交校验；
4. 团队统一使用标准化Prompt模板开发页面；
5. 试运行2个迭代，补充完善分片内组件示例，全团队推广。
