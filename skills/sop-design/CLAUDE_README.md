# 全文核心内容精简总结
## 一、核心痛点
大量开发者使用 Claude Code、Cursor 等AI编程工具时，AI频繁改出bug、乱换技术栈、代码风格不统一；根源是新会话AI无项目上下文，只能自行猜测需求，反复沟通返工。
## 二、核心工具：CLAUDE.md
1. **定义**：项目根目录Markdown文件，Claude Code新建会话自动读取，相当于给AI的项目入职手册，内置技术栈、命令、代码规范等背景信息。
2. **局限性**：仅为建议规则，非强制配置，指令越模糊、篇幅越长，AI遵守度越低；50行左右遵循率94%，400行仅71%。
3. **通用标准 AGENTS.md**
    跨AI工具通用规范标准，支持Cursor等30+工具；Claude可通过`@AGENTS.md`导入实现互通，可用于开发、图文、数据分析等全场景约束AI工作流。
## 三、写好CLAUDE.md的8大核心技巧
1. **篇幅控制200行内**
    占用上下文窗口，指令过多会全面降低遵守度；每条内容自问：删掉AI会不会出错，无用内容直接删除。
2. **只写AI无法自行推断的内容**
    ✅ 必写：特殊构建/测试命令、自定义代码风格、团队Git规范、项目独有架构、特殊环境配置、高频踩坑点
    ❌ 不写：代码可读取到的信息、通用语言规范、完整API文档、空泛要求（代码整洁、高性能等）
3. **正面指令替代否定句（规避白熊效应）**
    禁止写“不要XX”，直接写明应当怎么做，避免反向激活禁用内容。
4. **指令具象、可验证**
    杜绝模糊描述，明确路径、格式、执行命令、缩进、字符限制等可落地标准。
5. **区分规则建议与强制约束**
    CLAUDE.md做软性规范；格式化、测试、危险命令拦截等硬性操作使用Claude Code Hooks自动执行。
6. **大型项目拆分路径规则**
    新建`.claude/rules/`目录，通过YAML限定规则仅对指定文件路径生效，减少上下文占用。
7. **按需引用文档（渐进式披露）**
    用`@`语法关联`docs`下细分文档，标注触发阅读场景，AI仅在对应需求时加载，不占用基础上下文，官方称“即时上下文”策略。
8. **让AI迭代维护文档**
    AI出错修正后，直接指令其更新CLAUDE.md沉淀规则；搭配Auto Memory自动记忆项目开发模式，可通过`/memory`查看编辑。
## 四、快速创建CLAUDE.md三种方式
1. 命令生成：`/init`自动分析项目生成基础文件，人工校验删减优化；
2. 对话沉淀：先正常开发，结束后让AI从对话提炼规范生成文档；
3. 参考开源案例：awesome-claude-md、awesome-claude-code仓库获取多技术栈模板。
## 五、团队/多项目进阶用法：四层优先级配置
加载顺序由先到后，**优先级从低到高**：组织级规范（强制不可覆盖）→ 用户全局`~/.claude/CLAUDE.md` → 项目根CLAUDE.md（提交Git团队共享）→ 本地CLAUDE.local.md（私人配置，不上传）
- 团队方案：Git托管项目级文件，Code Review发现AI问题同步更新，沉淀团队统一开发标准；
- 关键提醒：重要规则必须写入文件，仅口头指令会在上下文压缩`/compact`后丢失。
## 六、规则失效排查流程
1. `/memory`命令确认文件是否正常加载；
2. 检查指令是否模糊、无法落地；
3. 排查多规则文件间是否存在冲突；
4. 强约束操作改用Hooks而非文本规则。
## 七、核心观点
README.md写给人，CLAUDE/AGENTS.md写给AI；核心逻辑是精炼、精准、可落地，从20行基础版本起步，随项目迭代完善，大幅减少重复沟通、统一代码风格、降低AI生成bug概率。
